# Streamverse

Streamverse is an open-source IPTV streaming web application. It aggregates publicly listed live television playlists, presents them in a fast React interface, and proxies streams when needed so browsers can play HLS sources that would otherwise fail because of CORS or hotlink rules.

The product is designed to run without user accounts, without a traditional database, and without advertisements. Favorites stay on the local device. Channel catalogs live in JSON files that a scheduled GitHub Action refreshes from upstream repositories.

This repository is the complete application: backend API, frontend UI, maintenance scripts, and the automation workflow.

## What Users See

- A two-pane live TV workspace: player on the left, searchable catalog on the right
- Category chips for All, Bangladesh, India, Sports, News, Kids, Movies, Music, Entertainment, Documentary, Religious, and related groups
- Instant search over the loaded catalog
- Favorites stored in the browser
- Dark and light themes
- Custom logo upload for personal branding
- HLS playback with quality selection, picture-in-picture, fullscreen, and a floating mini player
- Online / unstable / offline status from the health checker
- Automatic fallback to `frontend/public/channels.json` when the backend is asleep or unreachable
- Social preview image generated by `frontend/api/og.tsx` on Vercel Edge

## Architecture

```
Browser
  -> Vite / React frontend (Vercel or any static host)
       -> GET /channels.json          static fallback catalog
       -> GET {VITE_API_URL}/api/channels
       -> GET {VITE_API_URL}/api/proxy?url=...
  -> Express backend (Render or any Node host)
       -> backend/data/custom.json
       -> backend/data/playlists.json
       -> live M3U fetches when needed
       -> in-memory cache
```

The frontend never requires a database. Zustand persists theme, branding, player, and favorites in localStorage.

The backend is optional at runtime. If it is down, the UI still loads the last committed static catalog.

## User Interface

The current UI uses an iOS-style liquid glass treatment:

- Frosted translucent header, sidebar, search field, chips, cards, and menus
- Backdrop blur plus saturation, inner highlight stroke, and soft ambient gradients
- Rounded controls and compact channel tiles
- Status colors: green online, amber unstable, red offline
- Light theme uses the same glass language on a pale blue-gray canvas

Primary CSS tokens live in `frontend/index.html` (`:root` and `html.light`) and `frontend/src/index.css` (`.glass`, `.glass-strong`, `.liquid-bg`).

## Automatic Catalog Pipeline

File: `.github/workflows/check-channels.yml`

Trigger:

- Daily at 04:00 UTC
- Manual run from the Actions tab (`workflow_dispatch`)

Each run:

1. `scripts/refresh_channels.py` downloads every enabled URL in `backend/data/playlists.json` and rebuilds `backend/data/custom.json`
2. `scripts/enrich_logos.py` fills missing logos from the iptv-org/database CSV catalog
3. `scripts/check_channels.py` sends HEAD requests, updates `channel-health.json` and `blocked.json`, and writes the alive subset to `frontend/public/channels.json`
4. If anything changed, the workflow commits as `streamverse-bot` and pushes

Because Vercel and Render redeploy on push, the live site receives the new catalog automatically.

Sources currently include iptv-org country and category playlists, Free-TV playlists, and additional community M3U repositories listed in `playlists.json`. To add another source, append an object:

```json
{
  "url": "https://raw.githubusercontent.com/example/repo/main/playlist.m3u",
  "enabled": true,
  "label": "Example Source"
}
```

Disable a source by setting `"enabled": false` instead of deleting it.

## Local Development

Requirements:

- Node.js 18 or later
- npm
- Python 3.11 only if you want to run the maintenance scripts locally

```bash
npm run install:all
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env
npm run dev
```

In a second terminal:

```bash
npm run dev:frontend
```

Defaults:

- Backend: `http://localhost:3001`
- Frontend: `http://localhost:5000`
- Frontend env: `VITE_API_URL=http://localhost:3001`

Useful root scripts:

- `npm run install:all` — install backend and frontend dependencies
- `npm run dev` — start backend
- `npm run dev:frontend` — start Vite
- `npm run build` — production frontend build into `frontend/dist`
- `npm start` — start backend in the current environment

Manual catalog refresh:

```bash
python3 scripts/refresh_channels.py
python3 scripts/enrich_logos.py
python3 scripts/check_channels.py
```

The first refresh can take several minutes because it fetches many playlists. Health checks are concurrent and may take longer depending on how many URLs are in the catalog.

## Environment Variables

Backend `.env`:

```
PORT=3001
NODE_ENV=development
```

Frontend `.env`:

```
VITE_API_URL=http://localhost:3001
```

Production frontend must set `VITE_API_URL` to the public backend origin, with no trailing slash.

## Production Deployment

### Frontend on Vercel

1. Import this repository
2. Set the project root to `frontend`
3. Framework preset: Vite
4. Add `VITE_API_URL` pointing at the backend
5. Deploy

`frontend/vercel.json` rewrites non-API routes to `index.html`. The Edge function at `frontend/api/og.tsx` serves `/api/og` as the Open Graph image.

### Backend on Render

`render.yaml` defines a Node web service:

- Build: install and build frontend, then install backend
- Start: `NODE_ENV=production node server.js` from `backend`
- Health check: `GET /health`

In production the backend serves `frontend/dist` when that folder exists, so a single Node service can host both API and UI if you prefer not to split hosts.

### Required GitHub permissions

The workflow needs `contents: write` so it can commit catalog updates. Enable Actions on the repository. The first successful run creates or updates the generated JSON files.

## streamverse-bot Identity

The workflow commits as:

- Name: `streamverse-bot`
- Email: `streamverse-bot@users.noreply.github.com`

This is a commit identity, not a separate GitHub user. GitHub will show the default identicon unless you create a dedicated GitHub account named something like `streamverse-bot`, upload `.github/streamverse-bot.svg` (or a PNG export of `frontend/public/logo.svg`) as that account's avatar, and change the workflow `user.email` to that account's noreply address.

The product mark used in the UI and suggested for the bot is the rounded play-button square in `frontend/public/logo.svg`.

## API Surface

- `GET /health` — process health
- `GET /api/channels` — paginated / filtered catalog
- `GET /api/channels/categories`
- `GET /api/channels/featured`
- `GET /api/channels/countries/:code`
- `GET /api/proxy` — media proxy

Exact query parameters are implemented in `backend/routes/channels.js`.

## Data Files

| File | Generated | Purpose |
| --- | --- | --- |
| `backend/data/playlists.json` | No | Source list you edit |
| `backend/data/custom.json` | Yes | Full merged catalog |
| `frontend/public/channels.json` | Yes | Static fallback for the UI |
| `backend/data/blocked.json` | Yes | Offline IDs skipped by the API |
| `backend/data/channel-health.json` | Yes | Streak history |
| `backend/data/featured.json` | Optional | Featured overrides |

Empty stubs are valid. Scripts overwrite generated files on the next run. Do not hand-edit generated files if the workflow is enabled; your edits will be replaced.

## Troubleshooting

Backend will not start:

- Run `npm install` inside `backend`
- Confirm `PORT` is free

Frontend shows no channels:

- Confirm `frontend/public/channels.json` is valid JSON
- Confirm `VITE_API_URL` is reachable from the browser
- Check the browser console for `/channels.json` or `/api/channels` failures

A channel says stream unavailable:

- The upstream URL may be geo-blocked, expired, or offline
- Use Next Channel
- Wait for the next health-check run

Workflow does not commit:

- Actions must be enabled
- The default branch must be `main`
- The token used by Actions needs permission to push

Build fails on Render:

- Node version should be 18+
- Build command paths assume the repository root is the service root

## Security Notes

- Do not commit `.env` files
- Do not put secrets in `render.yaml`
- The proxy is rate-limited; keep it that way
- This software only organizes publicly listed playlist URLs. Respect local law and the terms of each source

## Design Decisions

- No login system
- No MongoDB / PostgreSQL
- Catalog is versioned JSON so the site can work while the backend sleeps
- Health history is kept so a single failed ping does not immediately hide a channel
- Comments were removed from application source to keep the tree compact
